That only works if one party can grant both. If a contribution arrives under
the AGPL alone, the project can never offer *that code* commercially — and
after a few such merges the commercial option is gone, one patch at a time,
without anyone deciding to end it. This agreement exists to prevent that.

## How to sign

Add a `Signed-off-by` line to each commit:

```
git commit -s -m "your message"
```

which appends:

```
Signed-off-by: Your Name <your@email>
```

That line means you agree to the terms above for that commit. Use a real name
and a reachable email — a pseudonym you actually go by is fine, but it has to
be one that identifies you consistently.

For a substantial contribution, or if you are contributing on behalf of a
company, say so in the pull request and expect to sign something more formal
before it is merged.

## Paid work

**A contractor or freelancer is a different case, and a sign-off is not
enough.** Work commissioned and paid for should be assigned outright rather
than licensed, so the project owns it and can license it either way without
tracing consent back through an invoice years later. See
[CONTRACTOR-IP.md](CONTRACTOR-IP.md).

## AI-assisted contributions

This project is itself AI-assisted and says so plainly in the README, so an
AI-assisted contribution is not unwelcome. But you are the contributor and you
are making the statements above: you are responsible for what you submit,
including that you have the right to submit it. Do not contribute code you have
not read and understood, and do not contribute output you have reason to think
reproduces someone else's licensed code. If a contribution is substantially
machine-generated, say so in the pull request — see the note in
[CONTRACTOR-IP.md](CONTRACTOR-IP.md) on why authorship is worth being careful
about here.
